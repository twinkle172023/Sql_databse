Compiler Design Project Integration Guide

How our SQL Injection Detection Compiler analyzes query structures, token streams, and AST nodes.

1. What is SQL Injection?

SQL Injection (SQLi) occurs when an application takes untrusted user data and concatenates or interpolates it directly into an SQL command string before sending it to the database engine.

From a Compiler Design perspective, user input is supposed to be a literal value (operand). However, when user data contains special characters like ', OR, UNION, or --, the SQL lexical analyzer generates new syntax tokens (operators and keywords), resulting in a fundamentally mutated Abstract Syntax Tree (AST).

Vulnerable Query Construction

SELECT * FROM users WHERE username = 'USER_INPUT';
Problem: User input becomes part of the SQL syntax.

When the input is ' OR '1'='1, the tokenizer produces:
[LITERAL ''], [KEYWORD OR], [LITERAL '1'], [OPERATOR =], [LITERAL '1']
The logical tree changes from an exact equality check to an always-true boolean tautology.

Secure Parameterized Construction

SELECT * FROM users WHERE username = ?;
Solution: User input is treated strictly as data rather than SQL syntax.

The SQL statement is pre-compiled into a fixed AST with a placeholder ? before receiving user input. The value ' OR '1'='1 is bound directly into memory as a literal string. Quotes have zero syntactic power.

3. What Your SQL Injection Detection Compiler Should Detect

  • Tainted String Concatenation: Detect when SQL statements are formed by combining string constants with external variables (e.g. query = "..." + var or f-strings f"...{var}...") instead of parameterized bindings.
  • AST Node Mutation: Identify that user input expands the grammar tree into binary expressions (e.g., BinaryOp: OR) or multi-query statements rather than remaining a single literal node.
  • Lexical Token Boundary Violation: Flag queries where unescaped string delimiter tokens (' or ") appear within dynamic expressions.
  • Rule Recommendation: Suggest converting concatenated SQL into prepared statement syntax using ? (SQLite/MySQL) or $1 (PostgreSQL).

4. Viva / Project Presentation Workflow

  1. Step 1: Navigate to the SQL Injection Lab page.
  2. Step 2: Enter payload ' OR '1'='1 and click Run Vulnerable Query.
  3. Step 3: Click Copy Query or Download Query (.txt).
  4. Step 4: Pass the exported query string into your SQL-injection detection compiler.
  5. Step 5: Show your compiler's output (e.g. AST breakdown, tainted token alert, or rule violation).
  6. Step 6: Return to the lab, click Run Secure Query, and demonstrate that parameterized queries prevent the injection completely.
